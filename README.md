# HUFS 홍보실 장비대여 · 사진촬영지원 웹앱

기획안 v0.1(2026.10, 전략홍보팀)을 그대로 옮긴 웹앱입니다. 기획안 3쪽 구조대로 **Google Apps Script 웹앱 + Google Sheets(저장소) + 메일 발송**으로 만들었습니다.

| 기획안 | 구현 위치 |
|---|---|
| 4쪽 카메라 대여 신청 화면(일시·카메라 택1·악세사리·사유) | `src/Index.html` ‘카메라 대여’ 탭 |
| 5쪽 반납 후 1시간 여유 판정 규칙 | `src/Logic.js` `isOverlapping`, `findConflicts` |
| 6쪽 신청 → 시트 저장(직전 재확인) → 확정 메일(참조 hufspr) | `src/Code.js` `submitRental` (LockService로 동시 신청 차단) |
| 6쪽 신청 즉시 확정 · 최대 3일 (관리자 승인 없음) | `validateRental` |
| 7쪽 근무자 있는 시간만 촬영 신청 가능, 신청 = ‘접수’ | `getShootSlots`, `submitShoot` |
| 8쪽 관리자 배정(근무 학생 + 빈 카메라) → 메일 2통 | `adminGetAssignOptions`, `adminAssignShoot` |
| 9쪽 관리자 화면 4개 메뉴, ‘설정’ 탭 관리자 목록으로 판별 | ‘관리자’ 탭 (대여 현황·촬영지원 배정·장비 목록·근무시간표 + 설정 보기) |
| 10쪽 시트 탭 5개, 촬영 배정 시 대여예약에 ‘유형=촬영’ 한 줄 추가 | `SHEETS` 정의, `adminAssignShoot` |

## 처음 설치하기 (복사·붙여넣기, 약 15분)

코딩을 몰라도 됩니다. **붙여 넣을 파일은 2개뿐**입니다: [`deploy/Code.gs`](deploy/Code.gs), [`deploy/Index.html`](deploy/Index.html)
모든 단계는 **hufspr@hufs.ac.kr 계정으로 로그인한 상태**에서 하세요. 이 계정으로 배포해야 메일이 hufspr 이름으로 나갑니다.

### 1단계. 구글 시트 만들기
1. 크롬에서 [sheets.new](https://sheets.new) 를 엽니다. 빈 시트가 새로 열립니다.
2. 왼쪽 위 ‘제목 없는 스프레드시트’를 눌러 이름을 `홍보실 장비대여 DB`로 바꿉니다.

### 2단계. Apps Script 편집기 열기
1. 시트 위쪽 메뉴에서 **확장 프로그램 → Apps Script**를 누릅니다.
2. 새 탭에 코드 편집기가 열리고, 왼쪽 ‘파일’ 목록에 `Code.gs`가 하나 있습니다.

### 3단계. 파일 2개 붙여 넣기
**(1) Code.gs**
1. GitHub에서 [`deploy/Code.gs`](deploy/Code.gs)를 엽니다. 코드 상자 오른쪽 위의 **복사 아이콘(Copy raw file, 네모 두 개 모양)**을 누르면 전체가 복사됩니다.
2. 편집기로 돌아와 왼쪽에서 `Code.gs`를 누르고, 오른쪽 코드 영역을 클릭한 뒤 **Ctrl+A**(전체 선택) → **Ctrl+V**(붙여넣기)로 원래 내용을 바꿔 씁니다.

**(2) Index.html**
1. 왼쪽 ‘파일’ 옆 **+** 버튼 → **HTML**을 누릅니다.
2. 이름 칸에 `Index`라고 입력하고 Enter. (대문자 I, `.html`은 자동으로 붙습니다. 이름이 다르면 앱이 열리지 않습니다.)
3. GitHub에서 [`deploy/Index.html`](deploy/Index.html)을 열어 같은 방법으로 복사한 뒤, 새 `Index.html`에 Ctrl+A → Ctrl+V 합니다.

마지막으로 **Ctrl+S**(또는 위쪽 디스크 모양 저장 아이콘)로 저장합니다.

### 4단계. 시트 준비 (setup 실행)
1. 편집기 위쪽 도구 막대에 함수 이름이 적힌 상자가 있습니다. 눌러서 **`setup`**을 고르고, 옆의 **▷ 실행**을 누릅니다.
2. 처음 한 번은 ‘승인 필요’ 창이 뜹니다. **권한 검토 → hufspr 계정 선택 → 허용**을 누릅니다. (중간에 ‘확인되지 않은 앱’ 경고가 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 누릅니다. 직접 만든 앱이라 나오는 안내입니다.)
3. 아래 ‘실행 로그’에 ‘실행 완료’가 보이면 시트 탭으로 돌아가 보세요. 장비목록·대여예약·촬영신청·근무시간표·근무달력·설정 탭 6개가 생겼습니다.
4. 다시 편집기에서 함수 상자에 **`importFall2026Schedule`**을 골라 **▷ 실행**합니다. 26년도 2학기 근무표(학생 30명, 9/1–12/21 근무달력)가 들어갑니다.

### 5단계. 웹 앱으로 배포 (주소 만들기)
1. 편집기 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. ‘유형 선택’ 옆 **톱니바퀴** → **웹 앱**을 고릅니다.
3. 칸을 이렇게 채웁니다.
   - 설명: `장비대여 1차` (아무거나)
   - 다음 사용자 인증 정보로 실행(Execute as): **나 (hufspr@hufs.ac.kr)**
   - 액세스 권한이 있는 사용자(Who has access): **hufs.ac.kr 도메인 내 모든 사용자** (학교 이름으로 보일 수 있음)
4. **배포**를 누르면 ‘웹 앱 URL’이 나옵니다. **복사**해서 HANA 학생들에게 공유하면 끝입니다.

### 그 뒤에
- 장비 이름·캠퍼스, 근무 학생 이메일은 앱의 관리자 화면이나 시트에서 바로 고치면 됩니다. 다시 배포할 필요 없습니다.
- **코드가 바뀌었을 때**(이 저장소가 업데이트됐을 때)만 3단계처럼 두 파일을 다시 붙여 넣고 저장한 뒤, **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 누릅니다. 이렇게 하면 주소가 바뀌지 않습니다.
- `src/appsscript.json`(시간대·배포 설정)은 붙여 넣지 않아도 됩니다. 시간은 코드에서 한국 시간으로 직접 계산하고, 배포 설정은 5단계에서 고릅니다.

> 개발자용: `src/`가 원본이고 `deploy/`는 `node scripts/build-deploy.js`로 만든 결과물입니다. [clasp](https://github.com/google/clasp)로 올리려면 `.clasp.json.example`을 `.clasp.json`으로 복사해 scriptId를 넣고 `npx clasp push`.

## 근무시간표와 근무달력

- **근무시간표** 탭: 학생이름, 이메일, 근무조(1조/2조), 팀(A/B/C조, 참고용), 요일, 시작, 종료.
- **근무달력** 탭: 날짜별로 그날 근무하는 조(1조/2조/없음)와 메모. 달력에 없는 날짜와 ‘없음’인 날은 촬영 신청이 닫힙니다. 달력 탭이 아예 비어 있으면 조 구분 없이 모든 근무시간을 씁니다.
- 26년도 2학기 값은 홍보실 근무표 이미지를 옮긴 것이며 `src/Data2026Fall.js`에 있습니다. 다음 학기에는 두 탭을 비우고 새로 채우면 됩니다.
- 한 촬영 시간대를 학생 여러 명이 나눠 맡을 수 있습니다. 근무시간이 시간대와 조금이라도 겹치면 근무자로 잡고, 관리자는 배정 화면에서 나갈 학생을 여러 명 고릅니다. 고른 학생들이 비워 두는 시간(예: 9–11시 근무자만 있는 날의 11:00–12:00)은 배정 화면에 경고로 표시됩니다.

## 기획안에서 정해지지 않아 이렇게 가정했습니다

| 미정 사항(기획안 11쪽) | 이번 구현 | 바꾸는 방법 |
|---|---|---|
| 카메라 기종 수 (4쪽은 3종, 11쪽은 4종) | 11쪽 최신 결정대로 **4종**: 소니 a6500, 소니 a6700, 소니 M7, 니콘 (처음엔 모두 서울캠퍼스로 등록) | 관리자 → 장비 목록에서 이름·캠퍼스 수정 |
| 캠퍼스 | 대여 화면에서 **서울/글로벌** 캠퍼스를 먼저 고르고, 그 캠퍼스 장비만 보임. 장비마다 캠퍼스 지정. 촬영지원 신청도 캠퍼스를 먼저 고르고, 배정 때는 그 캠퍼스 카메라만 보임. 근무시간표에는 캠퍼스가 없어 근무 학생은 캠퍼스와 상관없이 후보로 나옴 | 설정 ‘캠퍼스’, 관리자 → 장비 목록 |
| 악세사리 1개만 vs 여러 개 | 카메라처럼 **드롭다운에서 1개** (선택 안 함 가능) | – |
| 악세사리만 대여 | **불가(N)** | 설정 ‘악세사리만대여허용’ = Y |
| 최대 대여 기간 | 학생 **3일**, 관리자가 직접 신청하면 제한 없음 | 설정 ‘최대대여일수’ |
| 대여 시간 선택 범위 | 08:00–22:00, 30분 단위 | `Client.html`의 `fillTimes` |
| 촬영 날짜 | 요일만이 아니라 **실제 날짜**를 고르고, 그 요일 근무시간표로 판정 | – |
| 근무자 판정 | 근무시간이 시간대와 **겹치면** 근무자(여러 명이 나눠 맡음). 같은 시간 이미 확정 촬영에 나간 학생은 제외 | – |
| 촬영 배정 카메라 | 대여와 같은 1시간 여유 규칙 적용 | – |
| 장비 1개 단위 판정 | 카메라·악세사리를 각각 한 줄씩 기록하고 각각 겹침 판정. 한 번의 신청은 ‘묶음ID’로 묶음 | – |
| 대여 상태 | 시트에는 예약·반납완료·취소만 저장. 화면에는 시작 전 ‘예약’, 대여 중 ‘대여중’, 반납 예정이 지났는데 반납 안 했으면 ‘반납 지연’ | – |
| 반납 | 학생이 ‘내 신청’에서 **반납 완료**를 눌러야 장비가 다시 빌릴 수 있게 됨. 반납 예정이 지나도 누르지 않으면 그 장비는 그 뒤 모든 시간에 대여 불가 | 깜빡한 경우 시트 ‘대여예약’ 상태를 ‘반납완료’로 |

| 학생 본인 취소 | 대여 시작 전이면 ‘내 신청’에서 예약 취소 가능 | – |

## 착수 전 학교 전산 담당과 확인할 것 (기획안 11쪽)

- **hufspr 계정과 학생 계정이 같은 Google Workspace(hufs.ac.kr)인지**: 앱은 로그인한 사람의 이메일을 `Session.getActiveUser()`로 읽습니다. 구글 문서에 따르면 ‘나로 실행’ 웹앱에서는 원칙적으로 이 값이 비지만, 개발자와 사용자가 같은 Workspace 도메인이면 이 제한이 보통 적용되지 않습니다. 다른 도메인이면 이메일이 비어 앱이 “접속할 수 없습니다”를 보여 줍니다. ([Session 문서](https://developers.google.com/apps-script/reference/base/session))
- **학교 Workspace에서 Apps Script 웹앱 배포가 허용되는지**
- **메일 발송 한도**: Apps Script 할당량 표 기준 Google Workspace 계정은 하루 수신자 1,500명, 일반 계정은 100명입니다. 학교 정책으로 더 낮을 수 있습니다. 발송이 실패해도 예약은 저장되고 화면에 실패를 알립니다. ([할당량 문서](https://developers.google.com/apps-script/guides/services/quotas))
- **학생 개인정보(이메일·사유) 보관 기준**

## 로컬에서 미리 보기 · 테스트

구글 계정 없이도 실제 화면을 띄워 볼 수 있게, 시트·메일을 메모리로 흉내 내는 개발 서버를 넣었습니다(`dev/`). 실제 배포에는 쓰이지 않습니다.

```bash
node dev/server.js 8080
# 학생:  http://localhost:8080/?as=hana01@hufs.ac.kr
# 관리자: http://localhost:8080/?as=hufspr@hufs.ac.kr
# 보낸 메일: http://localhost:8080/mails
```

```bash
npm run build     # src/ → deploy/ 붙여넣기용 파일 만들기
npm test          # 규칙·서버·deploy 파일 테스트 (Node 20+)
npm run test:e2e  # 브라우저 화면 테스트 (Playwright 필요)
```

## 로그인 화면

- 앱을 열면 로그인 화면이 나옵니다. **학교 메일** 칸에 @hufs.ac.kr 메일을 입력하고 ‘로그인’을 눌러야 들어갈 수 있습니다.
- @hufs.ac.kr 이 아닌 메일은 ‘학교 메일(@hufs.ac.kr) 계정이 있어야 신청할 수 있습니다’로 막힙니다.
- 실제 웹앱에서는 입력한 메일이 **지금 구글에 로그인된 계정과 같아야** 합니다. 다르면 막힙니다. 남의 학교 메일을 입력해 그 사람 이름으로 신청하는 것을 막기 위해서입니다. 비밀번호는 앱이 받지 않고 구글 로그인이 대신합니다. 모든 데이터 기능도 서버에서 구글 계정을 다시 확인합니다.
- 오른쪽 위 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
- 학교 사진: 시트 ‘설정’ 탭의 **로그인사진** 값에 `https://`로 시작하는 사진 주소를 넣으면 기본 그림 대신 그 사진이 나옵니다.

## 체험판 (demo/index.html)

- `demo/index.html` 한 파일이 시트·메일 없이 브라우저 안에서만 도는 체험판입니다. src/ 를 고친 뒤 `npm run build:demo` 로 다시 만듭니다 (`npm test` 가 최신인지 확인).
- 빈 상태로 시작합니다: 장비 목록(서울 8개)과 26-2학기 근무표만 있고 신청·대여 기록은 없습니다.
- 로그인 칸에 아무 @hufs.ac.kr 메일을 넣으면 그 계정으로 들어갑니다 (체험판에는 구글 로그인이 없어서 입력한 메일을 그대로 씀). 관리자 화면은 hufspr@hufs.ac.kr.
- 신청·취소할 때마다 이 브라우저에 저장되고, 위쪽 ‘기록 모두 지우기’를 누르면 빈 상태로 돌아갑니다.

## 사진촬영 지원 (관리자 전용)

- 사진촬영 지원 메뉴는 관리자(설정 탭 ‘관리자이메일’)에게만 보입니다. 학생 화면에는 메뉴와 ‘내 신청’의 촬영 목록이 나오지 않습니다.
- 서버에서도 촬영 시간대 조회·등록·취소를 관리자만 할 수 있게 막았습니다. 관리자가 등록한 뒤 관리자 → 촬영지원 배정에서 학생·카메라를 배정합니다.
